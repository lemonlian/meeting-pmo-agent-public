## 场景 E：飞书真实链路（2026-11-23，真机真账号）

用户输入（原话，未整理）：
> 明天下午吧，跟奔腾那边过一下质检这块，他们刘经理一直说我们响应慢，得定下来试点到底做哪几个店，不然下周又得拖；哦对可能还得叫上老周，他管交付。

处理过程与实测结果：

| 环节 | 动作 | 结果 |
|---|---|---|
| 环境自检 | `python3 tools/doctor.py` | 飞书可用（lark-cli 1.0.100），企微/钉钉缺失并给出安装指引 ✅ |
| 意图路由 | 判定为「要开会」，非异步 | 从一句话里抽出 5 个槽位 ✅ |
| 查忙闲 | `calendar +freebusy` 查发起人 13:00–19:00 | 全空，给出下午时段 ✅ |
| 建日程 | `calendar +create` 写入 11-24 15:00–16:00 | 成功，自动生成视频会议链接 ✅ |
| 会前待办 | `task +create` 截止 11-24 11:00 | 成功，带责任人与验收标准 ✅ |
| 跨公司参会人 | 客户方查不到忙闲 | 走 fallback：给 A/B 候选 + 邀约话术，不硬占时间 ✅ |

**本次实测暴露的缺口（比成功项更重要）**

1. 会议卡只存在于日程 description 里，**没有结构化落库**，无法按客户/项目聚合查询，复盘无从做起。
2. 从纪要抽取待办这一步**没有实现**，当前依赖人肉把行动项写回卡片。
3. 缺「目标达成判定」字段，会后无法回答「这个会到底有没有用」。
4. 待办与日程之间**没有双向引用**，改期后待办截止时间不会跟着动。
